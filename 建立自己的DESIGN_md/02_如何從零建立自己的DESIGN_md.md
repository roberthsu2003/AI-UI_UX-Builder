# 第二章：實戰教學 — 如何從零建立自己的 `DESIGN.md` ✍️

[⬅️ 上一章：認識 `DESIGN.md` 與九大標準結構](./01_認識DESIGN_md與九大標準結構.md) ｜ [🏠 返回 `DESIGN.md` 單元主頁](./README.md)

學生不需要一開始就憑空手寫 200 行的設計系統文件。根據你的專案起點不同，可以選擇以下**三種實戰路線**來建立專屬的 `DESIGN.md`。

---

## 🧭 三種建立路線總覽

| 路線 | 適用情境 | 核心工具 | 預估時間 |
| :--- | :--- | :--- | :--- |
| **路線 A：逆向萃取法** | 手邊已經有現成網站、品牌官網或靈感截圖 | 多模態 AI（Claude / Gemini）＋ 網站截圖 | 10 分鐘 |
| **路線 B：範本改寫法** | 想直接套用成熟科技品牌或現代網站的美學骨架 | `awesome-design-md` / Google Stitch | 15 分鐘 |
| **路線 C：從零訪談法** | 全新專案、沒有既有網站，只有主題與目標受眾 | 本單元 [DESIGN_template.md](./DESIGN_template.md) ＋ AI 訪談 Prompt | 20 分鐘 |

> [!TIP]
> **課堂建議**：三條路線**選一條**完成即可，接著所有人都要做後面的「實作 2-D ～ 2-F」，把 `DESIGN.md` 真正用在網頁上。

---

## 🧰 開工前準備：建立你的練習專案資料夾

本章所有實作都在同一個資料夾內完成，最後的成品就是你要繳交的作業：

```text
my-design-lab/
├── DESIGN.md          ← 本章主角（路線 A / B / C 擇一產出）
├── style-guide.html   ← 實作 2-D：樣式總覽頁
├── index.html         ← 實作 2-E：首頁
├── faq.html           ← 實作 2-E：FAQ 頁
└── refs/              ← 放參考截圖、參考範本
```

```bash
mkdir -p my-design-lab/refs && cd my-design-lab
claude        # 或用 Cursor / Antigravity 開啟 my-design-lab 資料夾
```

## 🔍 路線 A：從現有網站或截圖「逆向萃取」`DESIGN.md`（最推薦新手）

如果你在進行「既有網站改版」或「延伸設計新活動頁」，最好的起點是先讓 AI 看懂現有品牌的視覺DNA：

1. **準備素材**：擷取目標網站的電腦版與手機版整頁截圖（可參考 [方法一：多模態截圖分析](../如何評估現有的網站/01_多模態截圖分析.md)），或是複製該網站的核心 CSS / 網頁文字。
2. **使用下方 Prompt 讓 AI 產出初稿**：

```text
你是一位資深的設計系統架構師（Design System Architect）。
請仔細分析我上傳的網站截圖（或附上的網頁風格說明），為這個品牌逆向整理出一份標準格式的 `DESIGN.md` 文件。

請務必包含以下兩部分：
1. 頂部的 YAML Front Matter（整理出觀察到的精確色碼 tokens、字體類型、圓角與間距系統）。
2. 以下 9 個標準章節（使用繁體中文撰寫，專有名詞可保留英文）：
   - 1. Visual Theme & Atmosphere（視覺主題與氛圍）
   - 2. Color Palette & Roles（色彩系統與語意角色，請用表格呈現 Hex 與用途）
   - 3. Typography Rules（字體與排版層級）
   - 4. Component Stylings（按鈕、卡片、導覽列與表單樣式）
   - 5. Layout Principles（版面佈局與間距原則）
   - 6. Depth & Elevation（陰影與層次規則）
   - 7. Do's and Don'ts（為了避免風格跑偏，請列出 5 條設計護欄）
   - 8. Responsive Behavior（響應式行為）
   - 9. Agent Prompt Guide（給 AI 生成頁面時的執行備忘）

若原網站有明顯的視覺缺點（例如對比度不足、顏色過於雜亂），請在「2. Color Palette」或「7. Do's and Don'ts」中主動提出修正與收斂建議，而非照單全收。
```

3. **人工審核與定案**：將 AI 產出的內容儲存為專案根目錄的 `DESIGN.md`，檢查色碼是否合理、確認字體是否支援繁體中文（如 `Noto Sans TC`、`Noto Serif TC`），並移除不想要的舊網站毛病。

### 🛠️ 實作 2-A：在 Vibe Coding 工具中跑一次逆向萃取

1. 挑一個你喜歡的網站（學校、在地品牌、喜歡的咖啡店都可以），擷取電腦版與手機版截圖，存成 `refs/desktop.png`、`refs/mobile.png`。
2. 在 AI 工具中輸入（把上面那段完整 Prompt 的開頭換成引用檔案）：
   ```text
   請分析 @refs/desktop.png 與 @refs/mobile.png，
   依照下方規格逆向整理出 DESIGN.md，直接寫入專案根目錄：
   （貼上上方完整 Prompt 的「請務必包含以下兩部分」之後的內容）
   ```
3. **人工校色（重要！）**：AI 從截圖「目測」的色碼常常有誤差。用瀏覽器開啟原網站 → 右鍵「檢查」→ 點選元素查看實際的 `color` / `background-color`，修正 `DESIGN.md` 裡差距最大的 2～3 個色碼。

**📎 小範例：AI 萃取後你可能會看到的片段**

```markdown
## 2. Color Palette & Roles
| 語意角色 | Token | Hex | 使用時機 |
| :--- | :--- | :--- | :--- |
| 主背景 | `canvas` | `#F7F5F0` | 全站底色 |
| 品牌主色 | `primary` | `#2F5D50` | 「線上預約」按鈕、主要連結 |
| 次要文字 | `muted` | `#9A9A9A` | 日期、說明文字 |

> ⚠️ 修正建議：原網站 `muted` 文字 `#9A9A9A` 在淺底上對比度僅約 2.8:1，
> 未達 WCAG AA，建議加深為 `#6B6B6B`。
```

👉 注意最後那段「修正建議」——這就是 Prompt 裡「不要照單全收」那句話發揮的效果。

## 🧩 路線 B：參考開源範本或透過 Google Stitch 匯出改寫

如果你想借鏡成熟產品的精緻感，不必從頭摸索數值：

1. **從開源庫尋找靈感**：前往 [VoltAgent/awesome-design-md](https://github.com/VoltAgent/awesome-design-md) 瀏覽各類知名品牌的 `DESIGN.md` 結構，挑選一個在「資訊密度與版型氣質」上最接近你專案的範本。
2. **或從 Google Stitch 匯出**：若你已在 [Google Stitch](https://stitch.withgoogle.com/) 完成了氛圍探索（參考 [主題一：無設計稿的氛圍與視覺探索](../建立提案用的原型網頁/01_無設計稿的氛圍與視覺探索.md)），可直接匯出該畫布的 `DESIGN.md`，確保後續跨頁面開發的風格一致。
3. **在地化改寫（關鍵步驟）**：
   * **替換品牌主色與強調色**（切勿直接照搬他牌配色）。
   * **補上中文字體設定**：許多英文範本只寫 `Inter` 或 `Geist`，套用到繁體中文網站時會回退成系統預設字體（如新細明體或微軟正黑體）導致質感大降。務必在 `typography` 中加上 `Noto Sans TC` 或 `Noto Serif TC`。
   * **補充專案專屬的 Do's and Don'ts**：寫明你的導覽列結構與禁用元素。

### 🛠️ 實作 2-B：讓 AI 幫你「在地化改寫」開源範本

1. 在 `awesome-design-md` 中挑一個範本，把內容複製存成 `refs/source-DESIGN.md`（或從 Stitch 匯出後放進 `refs/`）。
2. 對 AI 說：
   ```text
   @refs/source-DESIGN.md 是我參考的設計系統。請保留它的「版型氣質、資訊密度、層次策略」，
   但改寫成適合我的專案：【專案主題，例如：新竹在地手作甜點店】。
   規則：
   1. 品牌主色與強調色必須換掉，不可沿用原品牌色。
   2. typography 必須加入 Noto Sans TC / Noto Serif TC。
   3. 第 7 章 Do's and Don'ts 請針對我的專案新寫至少 3 條。
   4. 在檔案最後加一段「與原範本的差異說明」，條列你改了什麼。
   完成後存成根目錄的 DESIGN.md。
   ```
3. 讀一遍「與原範本的差異說明」，確認改寫方向符合你的想法；不同意的地方直接請 AI 修改。

## ✍️ 路線 C：使用課程範本，從零建構專屬 `DESIGN.md`

若你正在做一個全新的期末專題或提案網站，可以直接下載／複製本單元的標準範本：

👉 **[點此開啟範本：DESIGN_template.md](./DESIGN_template.md)**

也可以搭配以下「互動式訪談 Prompt」，讓 AI 一步一步問你問題，幫你把範本填滿：

```text
我想為我的網頁專案建立一份完整的 `DESIGN.md` 設計規範文件。
請扮演我的品牌設計總監，每次只問我 3 個簡單的問題（例如：網站類型與目標受眾、想傳達的三個氛圍關鍵字、偏好的色調與參考對象）。
收集完我的回答後，請依照「YAML Front Matter + 9 大標準章節」的格式，幫我生成一份可直接儲存使用的繁體中文 `DESIGN.md`。
```

### 🛠️ 實作 2-C：與 AI 訪談，填滿範本

1. 把 [DESIGN_template.md](./DESIGN_template.md) 複製到 `my-design-lab/` 並改名為 `DESIGN.md`。
2. 在訪談 Prompt 最後加一句：「**最後請直接覆寫 @DESIGN.md，保留原本的章節結構。**」
3. 誠實回答 AI 的提問，**每一題都盡量回答具體畫面**，而不是形容詞。

**📎 小範例：一段好的訪談對話長這樣**

```text
AI ：Q1. 你的網站是做什麼的？主要給誰看？
     Q2. 用三個詞形容你希望訪客的感受。
     Q3. 有沒有你喜歡（或討厭）的參考網站或品牌？

我 ：1. 社團「山岳攝影社」招新網站，給大一新生看。
     2. 開闊、安靜、有點冒險感。
     3. 喜歡國家地理雜誌的大圖排版；討厭那種花花綠綠、很多動畫的社團網站。

AI ：Q4. 主色你偏向「森林綠／岩石灰／晨曦橘」哪一種？
     Q5. 照片會是主角嗎？大約占版面多少？
     Q6. 有沒有一定要放的區塊？（例如：活動照片牆、報名表單）
```

> [!TIP]
> 回答「討厭什麼」跟回答「喜歡什麼」一樣重要——它會直接變成第 7 章的 **Don'ts**。

## 🔬 實作 2-D：產生「樣式總覽頁」，用眼睛驗證 DESIGN.md（所有人必做）

`DESIGN.md` 是文字，你很難光看色碼就知道配起來好不好看。先讓 AI 把它「畫」出來：

```text
請根據 @DESIGN.md 產生一個 style-guide.html 樣式總覽頁（單一檔案，可直接用瀏覽器開啟），包含：
1. 所有色票方塊，標示 Token 名稱、Hex 與語意角色
2. H1 / H2 / H3 / Body / Caption 文字層級範例（用中文假文字）
3. Primary / Secondary / Disabled 按鈕，以及一張範例卡片、一個輸入框
4. Level 0～3 的陰影層次示範
所有數值必須來自 DESIGN.md 的 YAML，並定義在 :root CSS 變數中。
```

打開 `style-guide.html` 後檢查：
- [ ] 色票放在一起和諧嗎？有沒有某個顏色特別「跳」？
- [ ] 中文標題是不是真的顯示成 `Noto Serif TC` / `Noto Sans TC`？
- [ ] 灰色說明文字在背景上看得清楚嗎？

**發現不滿意？直接改 `DESIGN.md` 的數值，再請 AI 重新產生 `style-guide.html`。** 這個「改規範 → 看結果」的迴圈，就是設計系統的日常。

## 🏗️ 實作 2-E：用同一份 DESIGN.md 生成兩個頁面

```text
請嚴格遵循 @DESIGN.md，為【你的專案】製作 index.html 首頁，包含：
Sticky 導覽列、Hero、3 張特色卡片、一段故事／介紹區塊、頁尾。
CSS 變數請直接沿用 @style-guide.html 中的 :root 定義。
```

首頁完成後，**開一個新的對話**（模擬「隔天再做」、AI 已經忘記前面的上下文）：

```text
請嚴格遵循 @DESIGN.md，製作 faq.html 常見問題頁（手風琴展開式 6 題 + 聯絡表單）。
導覽列與頁尾必須與 @index.html 完全一致。
```

> [!IMPORTANT]
> **為什麼要開新對話？** 在同一個對話裡，AI 會「記得」剛剛的樣式，看不出 `DESIGN.md` 到底有沒有用。開新對話後還能長得一致，才代表你的 `DESIGN.md` 真的寫得夠清楚。

## 🔁 實作 2-F：抓到跑版 → 修改 DESIGN.md → 重新生成

AI 幾乎一定會在某些地方「自由發揮」。這時**不要只叫 AI 修頁面，而是要回頭補規範**，否則下一頁還會再犯。

**Step 1：請 AI 自我稽核**

```text
請比對 @index.html 與 @faq.html 是否符合 @DESIGN.md：
1. 列出所有未在 DESIGN.md 中定義的色碼、字體、圓角數值
2. 列出兩頁之間導覽列、頁尾、按鈕樣式不一致的地方
3. 列出違反第 7 章 Do's and Don'ts 的地方
請用表格呈現，先不要修改任何檔案。
```

**Step 2：判斷問題出在哪裡，修改對應章節**

| 你看到的問題 | 該修改 `DESIGN.md` 的哪裡 | 範例補充寫法 |
| :--- | :--- | :--- |
| FAQ 頁的連結突然變成預設亮藍色 | 第 2 章 + 第 7 章 | 「所有文字連結使用 `primary`，Hover 加底線，禁止瀏覽器預設藍色」 |
| 兩頁的卡片圓角一個 8px、一個 16px | 第 4 章 | 「所有卡片一律 `radius.lg`，卡片內圖片 `12px`」 |
| 中段區塊突然變成冷灰色背景 | 第 2 章 + 第 7 章 | 「區塊交替只能使用 `canvas` 與 `surface_alt`」 |
| 手機版三張卡片擠在一排 | 第 8 章 | 「`< 768px` 時所有格狀版面改為單欄」 |

**Step 3：用修正後的 `DESIGN.md` 重新生成**

```text
我已更新 @DESIGN.md（修改了第 __ 章）。請依照新規範修正 @index.html 與 @faq.html，
並在最後列出你改了哪些地方。
```

> [!NOTE]
> 請在 `DESIGN.md` 最底下新增一段 `## Changelog`，記錄每次為什麼修改，例如：
> `- v1.1：補上連結顏色規則（FAQ 頁出現預設藍色連結）`
> 這份紀錄也是作業評分的一部分。

## 🚀 建好之後怎麼用？四個常見實戰場景

當你的專案資料夾裡有了 `DESIGN.md` 後，可以這樣用：

1. **在 Claude / ChatGPT 網頁版使用**：開新對話時直接上傳 `DESIGN.md`，並在 Prompt 開頭寫：「**請嚴格遵循附件 `DESIGN.md` 的色彩、字體、元件與 Do's/Don'ts 規範，幫我設計以下頁面⋯⋯**」。
2. **在 Claude Code / Cursor / Antigravity 中使用**：將 `DESIGN.md` 放在專案根目錄，下指令時直接以 `@DESIGN.md` 引用，讓 AI 在建立首頁、內頁、活動頁時自動對齊同一套系統。
3. **搭配網頁設計 Skill 一起用**：在 [Claude Skill 實戰指南](../Claude網頁設計Skill實戰指南/README.md) 中，推薦使用 **`UI UX Pro Max`** 或 **`Claude Design Pro`**；當「強大的設計能力（Skill）」遇上「精準的品牌邊界（`DESIGN.md`）」，產出品質最穩定。
4. **作為團隊溝通規格書**：PM 可以直接把 `DESIGN.md` 裡的色碼表、字級表與元件規則交給設計師導入 Figma Variables，大幅減少來回對色的溝通成本。

## ✅ 自我驗收檢核清單（Student Checklist）

當你完成自己的 `DESIGN.md` 並請 AI 試做第一個頁面後，請檢查以下 5 件事：

- [ ] **字體有正確套用嗎？**（是否明確指定了繁體中文字體，而非讓瀏覽器回退到預設系統字體？）
- [ ] **色碼都有語意角色嗎？**（是不是只列了一堆顏色，卻沒寫哪個是背景、哪個是主按鈕、哪個是細邊框？）
- [ ] **有寫「不要做什麼（Don'ts）」嗎？**（是否明確禁止了不適合本專案的漸層、過多陰影或突兀色按鈕？）
- [ ] **用同一份 `DESIGN.md` 生成兩個不同頁面，看起來像同一個網站嗎？**（測試：分別生成「首頁」與「FAQ／聯絡我們頁面」，檢查 Header、Footer、按鈕與色調是否一致）
- [ ] **手機版（375px 寬度）不會破版或文字溢出嗎？**（特別檢查第 8 章響應式規則是否有效約束 AI）

> [!TIP]
> **怎麼看 375px 手機版？** 在 Chrome 按 `F12`（Mac：`Cmd + Option + I`）→ 點左上角的手機圖示（Toggle device toolbar）→ 選擇 iPhone SE 或手動輸入寬度 `375`。

## 📦 本單元作業繳交

請將整個 `my-design-lab/` 資料夾上傳（GitHub repo 或壓縮檔皆可），需包含：

| 檔案 | 說明 | 配分 |
| :--- | :--- | :--- |
| `DESIGN.md` | YAML + 9 大章節完整，色票皆有語意角色，至少 3 條 Don'ts | 40% |
| `style-guide.html` | 樣式總覽頁，數值與 `DESIGN.md` 一致 | 15% |
| `index.html` + `faq.html` | 兩頁風格一致（導覽列、頁尾、按鈕、色調），手機版不破版 | 30% |
