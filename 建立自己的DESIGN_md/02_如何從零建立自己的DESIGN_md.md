# 第二章：實戰教學 — 如何從零建立自己的 `DESIGN.md` ✍️

[⬅️ 上一章：認識 `DESIGN.md` 與九大標準結構](./01_認識DESIGN_md與九大標準結構.md) ｜ [🏠 返回 `DESIGN.md` 單元主頁](./README.md)

學生不需要一開始就憑空手寫 200 行的設計系統文件。根據你的專案起點不同，可以選擇以下**三種實戰路線**來建立專屬的 `DESIGN.md`。

---

## 🧭 三種建立路線總覽

| 路線 | 適用情境 | 核心工具 | 預估時間 |
| :--- | :--- | :--- | :--- |
| **路線 A：逆向萃取法** | 手邊已經有現成網站、品牌官網或靈感截圖 | 多模態 AI（Claude / Gemini）＋ 網站截圖 | 10 分鐘 |
| **路線 B：範本改寫法** | 想直接套用成熟科技品牌或現代網站的美學骨架 | `awesome-design-md` / Google Stitch | 15 分鐘 |
| **路線 C：從零訪談法** | 全新專案、沒有既有網站，只有主題與目標受眾 | 本單元 [DESIGN_template.md](./DESIGN_template.md) ＋ AI 訪談 Prompt | 20 分鐘 |

---

## 🔍 路線 A：從現有網站或截圖「逆向萃取」`DESIGN.md`（最推薦新手）

如果你在進行「既有網站改版」或「延伸設計新活動頁」，最好的起點是先讓 AI 看懂現有品牌的視覺DNA：

1. **準備素材**：擷取目標網站的電腦版與手機版整頁截圖（可參考 [方法一：多模態截圖分析](../如何評估現有的網站/01_多模態截圖分析.md)），或是複製該網站的核心 CSS / 網頁文字。
2. **使用下方 Prompt 讓 AI 產出初稿**：

```text
你是一位資深的設計系統架構師（Design System Architect）。
請仔細分析我上傳的網站截圖（或附上的網頁風格說明），為這個品牌逆向整理出一份標準格式的 `DESIGN.md` 文件。

請務必包含以下兩部分：
1. 頂部的 YAML Front Matter（整理出觀察到的精確色碼 tokens、字體類型、圓角與間距系統）。
2. 以下 9 個標準章節（使用繁體中文撰寫，專有名詞可保留英文）：
   - 1. Visual Theme & Atmosphere（視覺主題與氛圍）
   - 2. Color Palette & Roles（色彩系統與語意角色，請用表格呈現 Hex 與用途）
   - 3. Typography Rules（字體與排版層級）
   - 4. Component Stylings（按鈕、卡片、導覽列與表單樣式）
   - 5. Layout Principles（版面佈局與間距原則）
   - 6. Depth & Elevation（陰影與層次規則）
   - 7. Do's and Don'ts（為了避免風格跑偏，請列出 5 條設計護欄）
   - 8. Responsive Behavior（響應式行為）
   - 9. Agent Prompt Guide（給 AI 生成頁面時的執行備忘）

若原網站有明顯的視覺缺點（例如對比度不足、顏色過於雜亂），請在「2. Color Palette」或「7. Do's and Don'ts」中主動提出修正與收斂建議，而非照單全收。
```

3. **人工審核與定案**：將 AI 產出的內容儲存為專案根目錄的 `DESIGN.md`，檢查色碼是否合理、確認字體是否支援繁體中文（如 `Noto Sans TC`、`Noto Serif TC`），並移除不想要的舊網站毛病。

---

## 🧩 路線 B：參考開源範本或透過 Google Stitch 匯出改寫

如果你想借鏡成熟產品的精緻感，不必從頭摸索數值：

1. **從開源庫尋找靈感**：前往 [VoltAgent/awesome-design-md](https://github.com/VoltAgent/awesome-design-md) 瀏覽各類知名品牌的 `DESIGN.md` 結構，挑選一個在「資訊密度與版型氣質」上最接近你專案的範本。
2. **或從 Google Stitch 匯出**：若你已在 [Google Stitch](https://stitch.withgoogle.com/) 完成了氛圍探索（參考 [主題一：無設計稿的氛圍與視覺探索](../建立提案用的原型網頁/01_無設計稿的氛圍與視覺探索.md)），可直接匯出該畫布的 `DESIGN.md`，確保後續跨頁面開發的風格一致。
3. **在地化改寫（關鍵步驟）**：
   * **替換品牌主色與強調色**（切勿直接照搬他牌配色）。
   * **補上中文字體設定**：許多英文範本只寫 `Inter` 或 `Geist`，套用到繁體中文網站時會回退成系統預設字體（如新細明體或微軟正黑體）導致質感大降。務必在 `typography` 中加上 `Noto Sans TC` 或 `Noto Serif TC`。
   * **補充專案專屬的 Do's and Don'ts**：寫明你的導覽列結構與禁用元素。

---

## ✍️ 路線 C：使用課程範本，從零建構專屬 `DESIGN.md`

若你正在做一個全新的期末專題或提案網站，可以直接下載／複製本單元的標準範本：

👉 **[點此開啟範本：DESIGN_template.md](./DESIGN_template.md)**

也可以搭配以下「互動式訪談 Prompt」，讓 AI 一步一步問你問題，幫你把範本填滿：

```text
我想為我的網頁專案建立一份完整的 `DESIGN.md` 設計規範文件。
請扮演我的品牌設計總監，每次只問我 3 個簡單的問題（例如：網站類型與目標受眾、想傳達的三個氛圍關鍵字、偏好的色調與參考對象）。
收集完我的回答後，請依照「YAML Front Matter + 9 大標準章節」的格式，幫我生成一份可直接儲存使用的繁體中文 `DESIGN.md`。
```

## 🚀 建好之後怎麼用？四個常見實戰場景

當你的專案資料夾裡有了 `DESIGN.md` 後，可以這樣用：

1. **在 Claude / ChatGPT 網頁版使用**：開新對話時直接上傳 `DESIGN.md`，並在 Prompt 開頭寫：「**請嚴格遵循附件 `DESIGN.md` 的色彩、字體、元件與 Do's/Don'ts 規範，幫我設計以下頁面⋯⋯**」。
2. **在 Claude Code / Cursor / Antigravity 中使用**：將 `DESIGN.md` 放在專案根目錄，下指令時直接以 `@DESIGN.md` 引用，讓 AI 在建立首頁、內頁、活動頁時自動對齊同一套系統。
3. **搭配網頁設計 Skill 一起用**：在 [Claude Skill 實戰指南](../Claude網頁設計Skill實戰指南/README.md) 中，推薦使用 **`UI UX Pro Max`** 或 **`Claude Design Pro`**；當「強大的設計能力（Skill）」遇上「精準的品牌邊界（`DESIGN.md`）」，產出品質最穩定。
4. **作為團隊溝通規格書**：PM 可以直接把 `DESIGN.md` 裡的色碼表、字級表與元件規則交給設計師導入 Figma Variables，大幅減少來回對色的溝通成本。

## ✅ 自我驗收檢核清單（Student Checklist）

當你完成自己的 `DESIGN.md` 並請 AI 試做第一個頁面後，請檢查以下 5 件事：

- [ ] **字體有正確套用嗎？**（是否明確指定了繁體中文字體，而非讓瀏覽器回退到預設系統字體？）
- [ ] **色碼都有語意角色嗎？**（是不是只列了一堆顏色，卻沒寫哪個是背景、哪個是主按鈕、哪個是細邊框？）
- [ ] **有寫「不要做什麼（Don'ts）」嗎？**（是否明確禁止了不適合本專案的漸層、過多陰影或突兀色按鈕？）
- [ ] **用同一份 `DESIGN.md` 生成兩個不同頁面，看起來像同一個網站嗎？**（測試：分別生成「首頁」與「FAQ／聯絡我們頁面」，檢查 Header、Footer、按鈕與色調是否一致）
- [ ] **手機版（375px 寬度）不會破版或文字溢出嗎？**（特別檢查第 8 章響應式規則是否有效約束 AI）
