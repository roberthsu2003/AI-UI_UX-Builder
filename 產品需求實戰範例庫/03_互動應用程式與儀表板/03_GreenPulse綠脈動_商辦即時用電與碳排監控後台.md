| 項目 | 內容規格 |

| **主題名稱** | 《GreenPulse 綠脈動》企業總部與商辦大樓即時用電、空調負載與異常警示監控後台 |

## 🎯 產品需求規格（PRD & 資訊架構）

### 1. 專案背景與痛點
企業廠務與永續人員每天要同時看許多感測器數據，但傳統機電監控畫面往往像 1990 年代工業螢幕——滿屏紅綠閃爍令人視覺疲勞，且看到異常數字時也不知道該從哪個設備查起。本系統要求「冷靜、克制、資訊層級極度分明」。

### 2. 核心功能與無縫互動需求
1. **左側固定垂直導覽列（240px）**：Logo `GreenPulse 綠脈動`、導覽項目（`即時戰情總覽`、`樓層用電明細`、`異常警報`［附角標 `2`］、`碳排月報匯出`）。手機版收合為漢堡選單。
2. **頂部全域狀態列**：切換大樓下拉選單（`台北信義總部` / `新竹研發園區`）、**時間維度無縫切換膠囊（`今日即時` / `近 7 日` / `本月累計`）**、右上角「匯出盤查 CSV」按鈕（點擊彈出模擬下載成功 Toast 提示）。
3. **4 欄核心 KPI 指標卡**（隨大樓或時間切換即時更新數值！）：
   * 即時總用電負載（`kW`）
   * 累計碳排放量（`kgCO₂e`）
   * 對比前期節電率（`%`）
   * 目前異常警示數
4. **中段雙欄圖表與警報區（70% / 30%）**：
   * 左欄：用 **Chart.js** 繪製用電趨勢折線圖，加上一條水平紅色虛線標示「契約容量警戒線」。
   * 右欄：「即時異常警示清單」，列出目前 2 筆超標事件；點擊任一警示卡片會滑出右側「異常診斷與排查建議抽屜」。
5. **各樓層用電明細表**：1F–6F 的照明用電、空調用電、總度數與狀態標籤（`正常運作` / `接近警戒` / `尖峰超標`，**不可只靠顏色，必須同時含圓點圖示與文字**）。

### 3. 真實感繁體中文文案與預設素材（直接給 AI 使用）
* **台北信義總部（今日即時範例數據）**：
  * 總負載：`482 kW`｜今日累計碳排：`2,140 kgCO₂e`｜節電率：`-6.4%（較昨日省電）`｜異常數：`2 件`
* **2 筆即時異常警示事件**：
  1. `5F 核心機房・空調冰水主機負載過高`（超標 `+18%`）→ 建議排查：`檢查 2 號備援冰機是否誤同步啟動，或機房冷通道擋板氣密狀態。`
  2. `3F 研發中心・下班時段照明未關閉`（持續耗電 `24 kW`）→ 建議排查：`B 區會議室群組自動排程感測器可能離線，建議遠端重啟迴路控制器。`
* **樓層監控 5 筆資料**：`1F 迎賓大廳（正常）`、`2F 共同辦公區（正常）`、`3F 研發中心（接近警戒）`、`4F 營運與行銷部（正常）`、`5F 核心機房（尖峰超標）`。

## 🎨 視覺與 `DESIGN.md` 預設規範

* **氛圍關鍵字**：冷靜工業控制室美學、克制資訊密度、一眼辨識異常。
* **字體搭配**：`Noto Sans TC` + `Inter` + 數據一律使用 `JetBrains Mono`。

| Token 名稱 | Hex 色碼 | 語意用途 |
| :--- | :--- | :--- |
| `canvas` | `#F4F6F8` | 極淨冷灰白後台底色 |
| `surface` | `#FFFFFF` | 數據卡、圖表區與表格底色 |
| `sidebar` | `#0F172A` | 深石板藍左側導覽列 |
| `ink` | `#111827` | 深灰黑主文字 |
| `muted` | `#64748B` | 單位（kW / kgCO₂e）與時間戳記 |
| `primary` | `#0F766E` | 永續青綠色主要按鈕與折線圖主線 |
| `danger` | `#DC2626` | 超標警報與契約容量警戒線 |
| `warning` | `#D97706` | 接近警戒狀態標籤 |
| `hairline` | `#E2E8F0` | 1px 表格與卡片細邊框 |

> [!WARNING]
> **AI 壞習慣禁令**：禁止整張卡片塗成大紅或大綠（造成視覺疲勞），警示只用在小面積狀態膠囊與圖示；禁止切換時間維度後圖表完全不重繪。

## 🤖 AI 全流程控制 Prompt 模板

### Prompt A：一鍵生成數據聯動的 B2B 監控後台原型
```text
請讀取本份規格文件，為「GreenPulse 綠脈動」設計一個高專業度的 B2B 商辦用電與碳排監控後台原型（單一 HTML 檔，可使用 Tailwind CSS CDN 與 Chart.js CDN）。

要求：
1. 嚴格實作「左側固定深色垂直導覽列（240px）＋ 右側主戰情區」骨架（手機版自動收合導覽）。
2. 必備 JavaScript 互動與數據聯動：
   - 頂部切換「台北信義總部 / 新竹研發園區」或切換「今日即時 / 近 7 日 / 本月累計」膠囊時，上方 4 張 KPI 數據卡與 Chart.js 趨勢折線圖（含一條紅色水平虛線『契約容量警戒線』）須即時切換對應數據！
   - 點擊右側「異常警示清單」任一事件（如 5F 機房），從右側滑出「異常診斷與排查建議抽屜（Drawer）」，可點擊「標記已派工處理」。
   - 點擊右上角「匯出盤查 CSV」時，畫面底部出現精緻 Toast 通知。
3. 嚴格遵守冷靜控制室配色（#F4F6F8 / #0F172A / #0F766E），狀態標籤須「圖示＋文字」並存。
```

### Prompt B：透過 MCP 在 Figma / pen.dev 建立後台畫布
```text
請讀取本範例規格，透過 MCP 在畫布上建立「GreenPulse 綠脈動」戰情總覽畫框（1440px × 960px）：
1. 左側 240px 深色（#0F172A）固定垂直導覽列，右側主內容區採 #F4F6F8 底色與 4 欄等寬 KPI 卡片。
2. 中段雙欄（左 70% 用電折線圖佔位含警戒虛線標示，右 30% 即時異常警示卡片），下方為 1F–5F 樓層用電明細表格。
3. 完成後截圖檢查，確認狀態標籤（正常／注意／超標）克制清晰不刺眼。
```

## ✅ 成果驗收檢核清單

- [ ] 切換頂部時間範圍（今日 / 近 7 日 / 本月）或大樓選單時，KPI 與趨勢圖是否皆同步變化？
- [ ] 點擊異常警示後，是否滑出詳細排查建議抽屜而不需離開戰情總覽頁？
- [ ] 表格與警報中的狀態標籤是否做到「顏色 ＋ 圖示 ＋ 文字」三重識別，符合無障礙原則？
- [ ] 整頁在高資訊密度下，是否依然保持卡片整齊與明確視線焦點（不雜亂刺眼）？
- [ ] 左側垂直導覽列在 `375px` 手機寬度下是否妥善收合為抽屜選單？
