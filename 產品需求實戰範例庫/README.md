# 產品需求實戰範例庫：挑一個題目，動手做出真實作品 📋

動手實作 UI/UX 原型時，學員最常遇到的問題不是「不會操作 AI 工具」，而是**「題目太模糊」**。如果你只對 AI 說「幫我做一個咖啡店網站」，AI 只能給你千篇一律、缺乏靈魂的公版網頁。

本單元精選 **12 個貼近台灣在地情境的繁體中文產品需求（Design Brief / PRD）**，涵蓋 **Landing Page**、**多頁式網站** 與 **互動應用程式** 三大介面類型。你可以直接從中挑選一個題目，依循前一個單元 [創意發想](../創意發想/README.md) 找好參考靈感，再進入 [建立提案用的原型網頁](../建立提案用的原型網頁/README.md)、[建立自己的 DESIGN.md](../建立自己的DESIGN_md/README.md) 與後續實作，一路貫穿完成你的作品！

> [!TIP]
> **每份範例卡都包含四大要素**
> 1. **主題**：品牌名稱與一句話核心定位。
> 2. **介面**：明確定義屬於 `Landing Page`、`多頁式網站 (Web)` 或 `互動應用程式 (Web App / Mobile Web App)`。
> 3. **產品需求**：包含專案背景與目標受眾（TA）、必備頁面結構與核心功能、UI/UX 與視覺氛圍要求。
> 4. **可直接複製給 AI 的啟動 Prompt**：已經幫你整理好角色、功能規格與設計限制，複製貼給 Claude、Google Stitch 或 Antigravity 就能立即開始第一版原型！

## 🔄 如何使用這些題目？

1. **選題與定調**：從上方挑一個感興趣的題目，先到對應分頁複製它的「產品需求」與「啟動 Prompt」。
2. **補齊視覺靈感**：到 [創意發想](../創意發想/README.md) 找 2～3 個風格相近的真實網站截圖或 Figma Community 範本。
3. **發散與生成**：在 Claude Artifacts (Design)、Google Stitch 或 Antigravity 中貼上啟動 Prompt 與參考截圖，先求「資訊架構正確」，再微調視覺。
4. **固化規範**：把滿意的設計色碼、字體與元件整理進你的 [DESIGN.md](../建立自己的DESIGN_md/README.md)，讓後續延伸頁面維持一致！
