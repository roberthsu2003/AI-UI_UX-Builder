# 產品需求實戰範例庫：挑一個題目，用 `PRD.md` ＋ `DESIGN.md` 做出真實作品 📋

動手實作 UI/UX 原型與桌面應用程式時，學員最常遇到的問題不是「不會操作 AI 工具」，而是**「題目與需求太模糊」**。由於本課程**全程透過 AI 與 MCP 控制設計與產出**，你給 AI 的文件合約越清晰，產出的成果就越專業。

本範例庫依介面類型拆分為 **三大類別資料夾**，收錄 **12 個獨立且完整的繁體中文實戰範例檔**。為了訓練學員真正掌握 AI 協作流程，**每個獨立範例檔都統一提供以下六大模組**：

> [!TIP]
> **每個獨立範例檔的標準結構（開箱即用 + 兩階段實戰）**
> 1. **📋 專案基本定位**：主題、介面類型、目標受眾、建議專案資料夾結構。
> 2. **📄 可直接複製的 `PRD.md`**：完整的產品需求規格書（含背景痛點、頁面架構與真實中文資料），可直接 Copy 存成 `PRD.md`。
> 3. **🎨 3 種不同設計風格的 `DESIGN.md`（可直接複製）**：針對同一題目提供三套截然不同的視覺與設計系統（皆含 YAML Tokens 與規範章節），可任選一套或比稿後 Copy 存成 `DESIGN.md`。
> 4. **🚀 階段一（初版生成）Prompt 撰寫注意事項 ＋ `<details>` 參考 Prompt**：**先看注意事項自己一項一項寫出 Prompt**，寫完再展開「參考 Prompt」對照！
> 5. **🔄 階段二（模擬提案後修改）情境演練**：模擬提案給客戶／主管後收到的修改需求，練習「**先同步更新 `PRD.md` 與 `DESIGN.md`（記錄 Changelog），再請 AI 局部修圖改碼**」。
> 6. **✅ 成果驗收檢核清單**：檢驗初版與提案修改後的最終品質。

## 🔄 標準上課實作流程（建議每題 45～60 分鐘）

```text
Step 1：建立本機專案資料夾（如 my-project/）
Step 2：從挑選的範例檔複製「PRD.md」與 3 選 1 的「DESIGN.md」存入資料夾
Step 3：【階段一】依「注意事項」自己逐條寫 Prompt（寫完再看參考 Prompt）→ 生成初版
Step 4：【階段二】模擬提案被打槍／加需求 → 先請 AI 改 PRD.md 與 DESIGN.md → 再局部更新程式
Step 5：依照「成果驗收檢核清單」逐項檢查並微調完成！
```
