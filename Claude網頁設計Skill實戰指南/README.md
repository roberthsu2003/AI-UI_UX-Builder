## 💡 什麼是 Skill？為什麼做網頁需要它？

* **運作概念**：AI 本身具備撰寫 HTML/CSS/JS 網頁的能力，但若沒有交代細節，它只能依循最常見的一般做法生成。**Skill 本質上是一個資料夾**，裡面必定包含一份核心說明檔（以及部分附帶的參考規範與程式碼），告訴 AI 該遵循哪些工作規範、色彩配置、排版方式與字體搭配。
* **對設計產出的影響**：就像為新進設計師提供不同的《品牌設計手冊》，掛載不同的 Skill，同一個 Prompt 所產出的網頁視覺風格與完成度會有截然不同的表現。

## 🛠️ 如何在 Claude 中安裝與使用 Skill？

本實測在統一基準（模型 `Sonnet 5.5`、投入程度 `effort` 設為中等）下進行，安裝 Skill 主要有以下兩種途徑：

### 方法一：從 Claude 內建列表直接新增（以 `frontend-design` 為例）
1. 點擊 Claude 介面左下角的個人 ID → 進入 **設定（Settings）** → 點選 **Skills**。
2. 在搜尋框中搜尋目標名稱（例如 `frontend`）。
3. 點擊 **新增** 即可完成啟用。

### 方法二：從 GitHub 下載並手動上傳（以 `UI UX Pro Max` 為例）
當內建列表搜尋不到想要的 Skill 時，可從開源社群（GitHub）下載並手動匯入：
1. 進入該 Skill 的 GitHub 頁面，點擊綠色 **`Code`** 按鈕 → **`Download ZIP`** 下載整包專案。
2. 回到 Claude 的 **Skills** 設定頁 → 點擊 **`+`** → 選擇 **上傳 Skill** 並拖入 ZIP 檔。

> [!WARNING]
> **常見上傳失敗與排雷解法**：
> 若直接將整個 GitHub 專案的 ZIP 檔拖入上傳，常會因為內含過多額外文件與連結而**被系統擋下並報錯**。
> **正確做法**：先將下載的 ZIP 解壓縮，打開其中的 `skills/` 資料夾，找到核心 Skill 子資料夾（例如 `ui-ux-pro-max`），**只將該核心資料夾單獨壓縮成 ZIP** 後再重新上傳，即可順利通過檢查並完成安裝。

### 實作操作流程
1. 開啟新對話，上傳頁面所需的照片與 Logo（檔案較大時可分批上傳）。
2. 在輸入框中輸入 **`/`（斜線）**，從選單中明確選取該回合要測試的 Skill。
3. 貼上設計 Prompt 並送出。
4. 生成完畢後，點擊右上角 **下載單一 HTML 檔**，直接使用瀏覽器開啟即可預覽互動效果。

> [!NOTE]
> **特例說明（`Awesome DESIGN.md`）**：它並非標準 Skill 格式，而是一份設計規範文件（片中採用 Apple 風格規範）。使用時改以「在對話中附加該設計檔」，並在 Prompt 補上一句「請照這份檔案的風格設計」來驅動。

## 🥊 兩輪實測對決與評比結果

實測以虛構的台南老宅咖啡店**「木日 Kibi」**為題，所有選手使用同一組店內照片與 Logo，分兩輪驗證「嚴格規格執行力」與「自主設計美感」。

### 第一輪：免費版高難度技術與視覺實測（7 位選手）

本輪測試在**免費版環境**下，各選手能否精準落實高難度動態效果與完整資訊排版。

> [!NOTE]
> **關鍵技術名詞：什麼是 WebGL？**
> WebGL 是瀏覽器內建的繪圖功能（無需安裝任何外掛），能讓網頁直接呼叫電腦顯示卡即時運算 3D 場景、粒子或水波紋等動態畫面。由於實作難度遠高於靜態排版，非常適合作為測試 AI 與 Skill 技術實力的試金石。

<summary>📝 點此展開：第一輪完整測試 Prompt（台南老宅咖啡店品牌形象網站）</summary>

```text
幫台南老宅咖啡店「木日 Kibi」做品牌形象網站，做成單一 HTML 檔，可以用任何網路函式庫。第一屏要有 WebGL 液態咖啡效果，游標移過會起漣漪；往下捲要一鏡到底，從店外走到吧台。內容要有品牌故事、招牌品項、地址和營業時間、訂位按鈕。附上的照片和 logo 都要用到。
```

## ⚠️ 使用 Skill 的重要注意事項（官方文件觀點）

根據實測經驗與 [Claude Code 官方文件（Skills）](https://code.claude.com/docs/en/skills) 的說明，管理與使用 Skill 時務必注意以下原則：

1. **Skill 並非裝越多越好（會消耗對話額度）**
   * 已啟用的每一個 Skill，就算當次對話完全沒有用到，它的說明描述在**每一輪對話中都會佔用上下文額度（Token/Context）**。
2. **裝太多反而降低觸發準確度**
   * 當安裝過多 Skill 時，系統可能會省略部分 Skill 的說明摘要，導致 AI 更難判斷並找到真正該使用的 Skill。
3. **啟用不代表一定會被自動呼叫**
   * Skill 是否載入是由 AI 依據使用者需求自行判斷。實測中經常遇到「明明已開啟 Skill，但因 Prompt 未提及而完全沒被套用」的狀況。
   * **最佳實踐**：下指令時在 Prompt 中**明確點名要使用的 Skill**，或直接輸入 **`/`（斜線）手動指定**。
4. **區分每個 Skill 的專長領域**
   * 並非所有網頁類 Skill 都專精於「從零設計頁面」，有些 Skill 的強項其實是「審查與重構現有網頁」，選用時應配合當前任務階段（如提案生成 vs. 程式碼審查）。
